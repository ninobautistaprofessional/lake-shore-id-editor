## Fixes applied this session

1. **api.php line 159 — HTTP status code inside response array (FUNC-002).**
   `response([…,409])` emitted `"0":409` with HTTP 200 (success “false” but the
   duplicate was never communicated as such). Changed to `response([…],409)` —
   the duplicate student submission is now correctly rejected with **HTTP 409
   Conflict**.
2. **qa_api_test.php — removed deprecated `curl_close()` (PHP ≥8.0 no-op)**
   eliminating 〜70 deprecation warnings from every run and making the report
   readable.
3. **FILE-008 re-scoped as by-design check.** The public student portal previews
    its just-uploaded photo with a plain `<img>` tag (no session), so photos
    must stay directly fetchable. Mitigations confirmed at runtime:
    unguessable 32-hex file names + Apache `Options -Indexes` (dir listing 403).
    Assertion now verifies exactly that designed behavior (severity Info).
4. **`.htaccess` (`Options -Indexes`) added to each `backend/uploads/*` folder**
   (students, receipts, signatures, templates) — defense-in-depth; previously
   only inherited from `backend/.htaccess`.
5. **Data hygiene:** removed the leftover `qa_debug_user` and experimental test
   rows/files; verified prod rows (id_cards #1 “bautista mark nino a.”) intact.

## Known by-design decisions (documented, not silent failures)

- **Public signatories & student photos served without login** (see SEC-013,
  FILE-008): required for the student portal; protected by random names + no
   directory listing. For stricter hosting turn on Apache `Require all denied`
  and serve images through an authenticated PHP endpoint when the portal is
   switched to a login-based flow.
- **No DB-level UNIQUE constraints / foreign keys** — uniqueness + referential
  integrity are application-enforced (verified: 0 duplicate groups, 0 orphans).
- **forgotPassword does not return the reset token** (OOB delivery) — verified
  no token disclosure (SEC-010) and 30-min expiry with 1-time use (SEC-011).

# Phase 2 — Extended QA suite & server-side hardening (same day)

## New artifacts

- `backend/tests/qa_api_test2.php` — **42 additional adversarial cases** (grade
  band matrix, LRN format matrix, course allowlist, duplicate variations,
  staff-path parity, signatory mapping, search depth, malformed JSON, IDOR,
  interleaved edit consistency, **6-way parallel duplicate race**).
- `backend/tests/_lock_probe.php` — standalone concurrency probe (N parallel
  identical submissions → asserts exactly 1 insert).
- `backend/tests/qa_api2_run_latest.txt` — latest extended-suite output.

## Product fixes implemented (backend/api.php)

1. **Shared type validator `normalizeCardByType()`** used by BOTH the public
   `studentSaveCard` and the staff `saveCard` paths (previously only the React
   UI enforced these rules — the API accepted anything):
   - COLLEGE → course required + allowlist (the 8 official courses); grade_level
     and LRN forcibly cleared.
   - JUNIOR_HIGH → grade required, restricted to GRADE 7–10; course cleared.
   - SENIOR_HIGH → grade required, restricted to GRADE 11–12; course cleared.
   - LRN (basic-ed only) → optional but must be exactly 12 digits if present.
2. **Staff `saveCard` duplicate-check parity** with the public path
   (name + student_number / student_id_number / LRN → 409), excluding the
   record being edited so updates never flag themselves.
3. **Concurrency race closed (§24).** Both write paths now take a MySQL named
   lock `GET_LOCK('lsc_card_write',10)` around the duplicate-check + write
   window. During verification the instrumentation log exposed a second,
   subtler bug — the lock was being released *before* the insert on the
   no-duplicate path, re-opening the race (2 identical rows created). Fixed by
   releasing **only** on the 409 path and after the write. Probe now yields
   exactly **1 insert / 5×409** across repeated 6-way parallel runs
   (EXT-090 PASS).
4. **Search depth** — `cards` search now also matches `course`, `grade_level`,
   `section_name`; the React list filter (main.jsx) was extended identically.

## Harness corrections (qa_api_test2.php / qa_api_test.php)

- missing `$fixtureDir` bootstrap, deprecated `curl_close`, query-param bug in

# Phase 3 — High-Priority Audit Log System (same day)

## Implemented

- **DB**: `audit_logs` table (migration `database/migrations/2026_09_05_create_audit_logs.sql`,
  also appended to `id_system.sql`; applied to the live DB) —
  `id, user_id, action, entity_type, entity_id, old_value, new_value,
  ip_address, user_agent, created_at` + indexes for every UI filter.
- **Backend**: `backend/audit.php` helper — `auditLog()` (auto-captures the
  authenticated user, IP, user agent; JSON-encodes old/new; wrapped so a
  logging failure can never break the main operation) and
  `auditDiffFields()` (field-level edit diffs, `old_value` = pre-edit row
  snapshot, `new_value` = `[{field,label,from,to}]`).
- **Instrumented actions** (all 8 required + supporting security events):
  card status done (`card_marked_done`), staff edits (`card_updated` w/ per-field
  diff), card delete, print, template save/update/delete, signatory
  save/update/delete, user create/update/enable/**disable**, lost-ID
  approve/update/delete, card created, lost-ID submitted, login, logout,
  failed login, password reset requested.
- **Read endpoint** `auditLogs`: admin-only (`requireAdmin`), server-side
  pagination + `search` / `action` / `user_id` / `date_from` / `date_to` filters.
  No update/delete route exists for audit rows; the API is read-only by design.
- **UI**: new admin dashboard card + **Audit Logs** view (date/time, user,
  action, entity, details, IP; search, action/user/date filters, pagination,
  detail modal rendering FIELD / FROM / TO rows from the diff). Build passes
  (`npm run build` ✓).

# Phase 4 - Released ID Status (PRINTED -> RELEASED) (same day)

## Implemented

- Migration `database/migrations/2026_09_05_add_release_fields.sql` (applied to
  the live DB; base `id_system.sql` also synced - its `id_cards` DDL was stale
  and is now the authoritative schema): `status` ENUM extended with
  `'released'`; new columns `released_by` (INT UNSIGNED), `released_at`
  (DATETIME), `release_notes` (TEXT NULL), `student_received`
  (TINYINT(1) DEFAULT 0). `student_signature` was intentionally NOT added:
  the system only supports staff *signatory* signatures, not student
  signature capture (spec allowed this conditional).
- Backend `releaseCard` action (POST, existing staff/admin + CSRF gate):
  rejects IDs that are not PRINTED (409), persists released_by / released_at /
  release_notes / student_received, and writes audit event `card_released`
  with old_status=printed, new_status=released, release notes, IP and user
  agent. RELEASED is terminal: re-release and `setCardStatus` both 409.
- `cards` / `card` endpoints JOIN `users` to expose `released_by_name`.
- Frontend: status labels + filter chips
  (All | Request | Review | Approved | Printed | Released), Release ID button
  with confirmation dialog, and a released-info panel (released by, date/time,
  release notes, student received) on the card row and record modal.

## Verification (`backend/tests/qa_release_test.php` - 12/12 PASS)

Printed ID can be released; unprinted/done cannot; release fields persisted
with correct user and timestamp; status flips to released; the audit row
contains user, old/new status, notes, IP, user agent and time; no accidental
re-release (409 with data intact); RELEASED is terminal for setCardStatus;
permissions (anonymous 401 / missing CSRF 403); admin release path with
received unchecked; listing exposes released_by_name.
